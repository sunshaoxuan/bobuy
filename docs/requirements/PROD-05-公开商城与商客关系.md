# PROD-05: 公开商城与商客关系

日期：2026-10-22
状态：本地实现与核心流程验收完成；2026-10-23 已发布生产预览 20261023.1，发布验收见 deployment-task.md 和 REPORT-18

## 1. 本轮范围与优先级

本轮以手机体验为第一优先级，平板其次，桌面保持相同业务与视觉语言，按设备调整导航、栅格和结账布局。默认入口 `/` 为客户商城；维护入口为 `/admin`。2026-10-23 用户授权将当前版本发布至既有 bobuy.cc，并在后续需求完成必要检查后持续发布。沿用独立 bobuy 容器组，保留其他应用与休眠热备，避免新增测试环境。

生产预览保留真实目录。正式 SMTP、公共注册反滥用与账户恢复门禁完成前，生产注册和邮箱接口明确返回 503，现有商家登录继续可用。本地注册与测试收信能力不变。此状态不代表完整客户注册业务已放行。

本文件更新 PROD-01、PROD-02、PROD-04 中相同范围的首页、认证、客户激活及客户端视觉约定，其余业务要求保留。品牌为“宝宝败”。客户端采用现代黑白与珊瑚红操作强调、实物商品图片与零字间距，商家既有业务页面沿用原有组件。

## 2. 公开浏览与购物车

- 访客可读取已发布、出发日期未过期的行程，以及公开商品。公开 DTO 排除客户、采购成本、供应商报价与内部容量数据。
- 客户先选行程，商品归属于该行程商家；一个购物车仅包含一个商家的商品。更换商家时须确认清空原商品。
- 临时购物车保存在当前浏览器 localStorage，刷新可恢复。其内容不保证跨设备同步，退出账户不自动删除购物意图。
- 商品支持图片、详情、搜索、增减数量及删除。单商品最多 99 件，一次订单最多 50 种。
- 最新交互采用 Pinterest 式纵向瀑布流，取代单商品横滑。手机双列、平板三列、桌面按约 200 至 240px 列宽自适应，1440px 六列。卡片采用不同纵横比、12px 栅格间距和 CSS 20px 连续圆角完整裁切。白色画布、轻量搜索胶囊和底部渐隐保持图片主体清晰。图片铺满卡片，名称、价格白色叠图；品牌与详细说明进入详情查看，避免品牌小字与包装印字混叠。长名称最多展示两行，详情提供完整名称。手机固定底部导航，平板和桌面使用页头账户与购物车入口。
- 首批展示 6 件，滚动接近列表底部自动追加最多 6 件，已有卡片保持位置。保留手动加载按钮供观察器不可用时操作；搜索结果改变重置批次，空结果不显示加载按钮。本地 API 当前返回完整商品目录，此处为客户端渐进展示，不代表服务端分页。
- 商品卡右上角 + 采用 34px 半透明圆面、16px 图标、细边缘、12px 背景模糊和轻阴影，透明外层保留 44px 手机热区；悬停和按压提高圆面不透明度。打开数量设置，支持 1 至 99 件，确认才更新临时购物车，取消保持原数量。已加购商品再次设置时编辑其现有数量。
- 本次试点金额单位为 JPY；多币种计价、汇率与支付渠道接入不属于本轮。

## 3. 注册、邮箱与激活

- 到结账时引导注册或登录。注册提供 3 至 40 位字母、数字或下划线用户名、8 至 72 字符密码、邮箱；bcrypt 密码 UTF-8 最多 72 字节。
- 注册后获得客户登录会话，保留购物车。提交订单仍需客户明确确认。
- 验证码通过 SMTP 发送，6 位数字、10 分钟有效、哈希存储、每分钟最多重发一次、最多 5 次错误尝试。验证成功删除挑战记录。邮箱验证为账户全局事实。
- 未验证客户可登录、浏览和提交 NEW / UNPAID 待确认订单。邮箱状态及商家认可状态不自动触发支付、采购或订单确认。
- 商客关系以 `(merchant_id, customer_id)` 唯一。商家只能激活已向自己下单的客户，记录操作者与时间。A 商家认可对 B 商家无效，手工认可不会将邮箱标记为已验证。
- 2026-10-24：统一账号采用非空类型集合，CUSTOMER 为客户、AGENT 为商家；支持勾选一种或两种，同一商家可以同时向其他商家购买。历史 MERCHANT 在 V5 统一为 AGENT。
- 购物车结账注册固定创建 CUSTOMER，客户端无法通过附带角色字段提升身份。独立 `/account` 注册允许选择客户、商家或两者；注册账号均无平台管理员权限。生产两个注册入口继续受 SMTP、反滥用和账户恢复门禁控制。
- 平台管理员使用独立受保护的 platformAdmin 权限；既有 admin 商家账号经 V5 升级为平台管理员。平台用户管理可创建和编辑用户名、姓名、邮箱、密码、客户/商家类型及启用状态，至少保留一个类型。编辑空密码保留原密码，邮箱变更清除旧验证事实；禁止停用当前操作账号。界面和接口均不提供授予平台管理员权限的能力。
- 普通商家、客户均无全局用户管理权限。用户管理变更不替代邮箱验证或商家独立认可，不改变已有订单归属。

## 4. 下单与商家边界

- 服务端从登录身份确定客户，从行程确定商家，从商品读取有效价格，忽略客户端金额。隐藏商品、跨商家商品、过期或未发布行程不得结账。
- 购物车请求 UUID 与客户共同构成业务幂等键。同内容重试返回原订单，改变内容复用旧键被拒绝。客户行锁串行化同账户结账。
- `/admin` 供商家或平台管理员进入，`/admin/users` 及 `/api/admin/users` 仅平台管理员可用。平台权限不会绕过商家业务归属。认证每次请求重新读取账号启用状态和类型，撤销类型或停用后，旧令牌不能继续使用相应权限。
- 双类型账号通过 `/api/customer/` 查看自己的购买行程、订单与账单；商家工作台按自己的销售业务过滤。两个视图在接口中显式区分，客户接口仅允许 CUSTOMER。
- 旧客户账单及聊天使用的内部行程接口仅返回本客户已有订单关联的行程；访客和客户浏览公开行程使用公开 DTO。
- 客户余额和历史流水只汇总当前商家行程，行程账单的上期结余只统计同一商家。旧合伙人全局钱包与全局账户写入接口暂不向商家开放；商客激活使用新的客户入口，合伙人钱包恢复需单独完成租户化验收。
- 私聊参与者必须包含当前身份，并有该客户与商家的订单关系；订单和行程群聊按资源归属授权。

## 5. 数据升级与本地环境

- Flyway V4 增加邮箱验证事实、商客关系、验证码挑战、商品与供应商商家归属及数据库序列。已有单 AGENT 目录映射到该商家；多个 AGENT、无 AGENT 的非空目录须先明确归属，迁移主动失败。重复用户名或邮箱须先清理，禁止猜测合并。
- Flyway V5 将单值 role 转为 JSONB roles 集合，数据库约束拒绝空集合、未知类型、重复类型，删除旧字段。保留账号、密码、关系和业务数据。升级期间停止应用写入，备份并验证恢复；回滚须恢复迁移前数据库和旧应用，禁止直接以旧应用访问 V5 结构。
- 升级前备份数据库，检查小写用户名和邮箱重复、商家数量与目录归属。Flyway 已应用版本再次启动不重复迁移。回滚采用停止新服务、恢复升级前快照及对应旧版本，禁止旧代码与新注册流并行写入。
- 唯一测试项目 `bobuy-local`：web、backend、PostgreSQL、Redis、RabbitMQ、Mailpit，共用项目网络和命名卷。入口仅绑定回环地址 18080，邮件收件箱 18025。
- `scripts/local-test.ps1` 统一启动、查看或停止这一组。禁止复制 Compose 项目、使用全局 prune 或改变其他应用。
- 2026-10-24 用户纠正：单套测试约束同时覆盖镜像留存。本机常驻 BoBuy 应用镜像仅为 `bobuy/local-web:current`、`bobuy/local-backend:current`，另保留该组实际使用的四个基础服务镜像和数据卷。生产发布镜像在本机完成传输、发布及验收后，核对全部容器引用，再按精确标签清理本机副本；远端发布和回滚材料遵循生产保留策略。重建遗留的无标签镜像须证明属于本项目且无容器引用才可清理，不允许全局清理其他项目或共享缓存。
- 测试商品与演示账户只在本地 seed 开关下使用，不代表真实商品库存、商家报价或可履约订单。

## 6. 四语品牌与商家工作台

- 商城和 `/admin` 使用同一品牌：简中「宝宝败」、英文「BoBuy」、日文「ボボバイ」、繁中「寶寶敗」。菜单、表单、状态、购物车、注册、邮箱验证与系统组件均通过 i18n 资源维护。
- 两端均提供四语切换，保存用户选择，同步页面语言、标题、日期组件与接口 Accept-Language。切换语言保留购物车及当前表单，业务枚举和接口字段保持稳定。
- 四份界面资源必须具有相同键集合和占位符；服务端错误语言不依赖部署主机默认语言。商家商品缺少当前译文时，按 i18n 规范显示已有商品内容。
- 后台采用固定侧栏、顶栏与内容栅格，内容从顶栏下方开始。手机采用抽屉导航、单列表单，平板与电脑采用双列表单，宽表格仅在自身区域滚动。商城保留已确认的 Pinterest 瀑布流效果。
- 唯一本地容器组和生产应用隔离约束继续有效。实施与验收见 [PLAN-60](../plans/PLAN-60-四语品牌与商家工作台.md)。
