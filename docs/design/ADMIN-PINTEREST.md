# Bobuy administration: product-led visual language

The Pinterest reference applies to administration as well as the storefront. Retain the Bobuy red mark, restrained ink navigation, soft neutral canvas, readable Japanese/Chinese sans-serif type, generous spacing and real CSS image corners. Product photographs lead browsing; structured forms lead editing. Do not make editable fields into a masonry wall or repaint source images.

Product records default to a responsive image-card collection. The same records retain an explicit compact-management view and original bulk/AI workflows. Cards use complete official images with contain fitting, an image-count badge, localized name, supplier ITEM, readable taxonomy and a distinct pending-price state. Missing images are labelled, never replaced by unrelated generic product art. Merchant/API media types may be uppercase; normalize only the display representation. Existing archive/admin authorization remains authoritative.

The canonical editor opens on the right on desktop and from the bottom on mobile at 80% of the available visual viewport (80dvh fallback), respecting safe-area insets. A compact contained main image and selectable filmstrip sit above three main tabs: product details, languages/descriptions, and images/sources. Main-image selection, ordering, removal and upload remain explicit. Four languages use one segmented selector within the copy tab rather than nested tab hierarchies. Switching tabs preserves unsaved values. Required Japanese-name errors open the copy tab and focus its field; image-provenance errors open the image tab. Shared uploads still require provenance checks; saving still requires review and versioned preview. The drawer footer keeps review/save reachable independently of form scrolling. Close and mobile browser-back warn about unsaved edits; cancelling keeps the edits. Compact management stays available; no pricing/stock/publication semantics change.

Maintain 44px touch targets, keyboard focus, native scrolling and reduced-motion behavior. Hover effects apply only to fine pointers. Image pixels remain untouched; contain fitting preserves packaging text and all image edges. Do not simulate corners with artwork or broad overlays.

## Shared image inspection

The catalog editor's main image opens the same fullscreen inspection component as the customer product detail. A single click/tap closes after a340ms double-tap window; a double click/tap toggles fitted/native pixels, and native-size dragging pans within the actual image edges without changing images or closing. Small sources are never enlarged beyond their natural size. Fit-mode swipes retain the existing continuous rail, neighbor reveal, bounded navigation and reduced-motion settling. Escape is captured by the fullscreen layer before underlying drawers can receive it; closing restores focus to the opener. The editor keeps its draft, selected tab/language and selected gallery image. The viewer makes no API calls, uploads or business writes.

Acceptance uses the existing local Playwright/Vite environment with read-only fixtures. Mouse and CDP touch input cover double/single discrimination, held pan frames, native dimensions, small images, Escape/focus, unsaved drafts, image selection and the original customer swipe/vertical-scroll behavior. Official image pixels remain unchanged; synthetic2000x1600 and120x90 images exercise size boundaries. This batch is local only and requires its own production approval before push/deployment.
