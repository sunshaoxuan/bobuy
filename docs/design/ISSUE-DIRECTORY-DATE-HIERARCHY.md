# 期数目录日期层级（2026-11-10 修订）

本规范是本次反馈后的新修订，不代表旧版已具备同等设计依据。

需求依据：用户要求紧凑目录突出日期、公开件数、真实供应商；按期次日期倒序，编辑与增补不改变排序。2026-11-10 用户指出同位置标签不同及说明堆叠。

统一显示规则：

1. 左侧日历只放年月日数字，不放“期次日期／发布”等类型标签。件数和供应商保持。
2. 右侧仅一条日期说明，统一位置、字号、层级。有效且审核通过的 issueDate 优先，标明期次日期；没有该事实时，使用有效 publishedAt，明确标明发布日期（日本时间）。两者不能互相冒充。
3. 同时有两种日期时，小卡只显示优先的期次日期；完整来源信息仍保留在无障碍名称与原数据中。不在目录叠加第二个发布时间、待核对状态或全局审核说明。
4. 两者均无效或缺失时保留中性日历图标，不猜标题、更新时间或今天。无障碍名称仍说明来源缺失，不造日期。
5. 收起、展开、桌面、手机和四语使用同一结构。日期来源、JST转换、服务器排序、唯一当前项、深链和权限均不改。

验收：审核源日、仅发布时间、缺日期、两类日期不同、JST跨日、旧期增补及稳定顺序；四语 × 宽窄结构中已知日期每卡仅一条可见说明，左侧无类型文字，无重复审核提示；源日期与发布时间仍可区分。正式构建的真实手机/桌面视觉需要独立验证。

旧版事实：IssueDirectory.tsx 分别渲染日期块类型、主日期、副发布时间和审核提示；旧组件测试明确要求这些元素，16组真实页面验收也接受了保留待核对提示。因此缺口是设计/验收标准本身未限制重复层级，不是单纯漏执行日期测试。此修订不修改历史验收记录。
