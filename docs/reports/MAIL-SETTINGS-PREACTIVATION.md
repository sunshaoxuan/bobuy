# Mail settings: locally verified, production activation pending

This batch adds `/admin/settings` (System settings · Mail) to the existing administrator workspace, visible only to platform administrators. The server independently restricts all `/api/admin/settings/**` reads, saves and test sends to `ROLE_PLATFORM_ADMIN`. Ordinary merchants/customers cannot access these endpoints. The production site remains **20261027.1**, with registration and sales closed. This batch has not been deployed or configured in production.

## Implemented

- SMTP host, port/encrypted mode, username, From and Reply-To settings, four UI languages, write-only masked password input, blank-password retention and optimistic edit versions. Changing the destination/identity requires password re-entry. A saved disabled configuration does not send registration mail.
- V18 adds only `bb_mail_settings` and `bb_mail_settings_event`; it seeds no settings, passwords, keys or enabled state. Audit events contain only actor, timestamp, settings revision and operation/result, without submitted values, recipients, messages or secrets.
- Passwords use AES-256-GCM with a fresh 96-bit nonce, 128-bit authentication tag and identity-bound additional authenticated data. The DB stores ciphertext and key ID. The versioned keyring is loaded from an external protected file; no key is stored in the DB. Missing keys prevent password storage/activation, and malformed/tampered ciphertext fails closed. Old key versions can decrypt retained ciphertext; saving re-encrypts under the active version.
- The default server allowlist contains only `mail.briconbric.com`. Arbitrary hosts/IPs and unencrypted modes are rejected. STARTTLS/587 is mandatory for the current server, with TLS 1.2/1.3, normal chain and hostname checks, bounded connection/read/write waits and SMTP/auth debugging disabled. TLS/465 is supported as an explicit encrypted alternative; no trust-all option exists.
- Controlled test sends use only saved settings, a fixed token-free message and a deployment-approved recipient list (empty by default). The current single-instance core limits tests to one per 60 seconds; this in-memory limit resets on process restart and must be made shared if core is replicated. Unapproved recipients cannot be entered through the UI or supplied by direct requests. SMTP acceptance is not reported as inbox delivery.
- Existing six-digit registration verification, hashed token storage, expiry, retry, resend and one-time-use behavior are reused. Messages now support ja/zh-CN/zh-TW/en and point to the fixed legitimate `https://bobuy.cc/account` page. With no DB configuration, the existing sender path is preserved; once a DB configuration exists, disabled/failed encrypted delivery does not silently fall back to another identity.
- Mail-controller parsing/validation/transport failures are sanitized locally so global exception logs cannot echo a submitted password or AUTH transcript. API responses never return plaintext or ciphertext.
