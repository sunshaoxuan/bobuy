# Source-reviewed issue date — normal management wiring candidate

The normal owned recommendation detail page exposes source-date review for both draft and published issues. The entry uses the existing standalone editor; a customer, another merchant, missing owner metadata or missing token gets no entry or private request. The UI gate complements the unchanged server ownership/role checks and does not grant permission.

GET/PUT call `/api/merchant/recommendations/{id}/issue-date` with the token captured for that actor/session. There is no cross-session token refresh or automatic write retry. A token/account/session change invalidates late reads and writes. The PUT body is reconstructed from exactly `issueDate`, `sourceRef`, `sourceHash`, `version`, `reviewed`; client identity/reviewer/role fields are never sent. Evidence remains private editor state. Only the public issue date/source and post version can enter the parent detail.

The parent article baseline must match the version read by the date editor. A newer private review cannot silently promote an old parent article record to that version. A version conflict requires the existing explicit page reload, which preserves unsaved article text and the date draft; the operator then re-reads and reviews the date source against the fresh parent version. A successful result is merged only into the exact parent post/version for which it was written. Publication state/time/author, title/body/translations, article sourceHash, prices, gallery and the complete item array are preserved. Unsaved source-date work participates in the existing leave guard; collapsing the editor retains its draft.

All 27 copy keys are present in Chinese, Traditional Chinese, Japanese and English. Unknown dates remain blank/explicitly unknown; no publication date, offer window, title text or today's date is inferred. Date input is a source calendar day. The source reference/hash are supplied and reviewed by the operator; this UI does not retrieve source content or prove its external hash.

Validation: the unchanged editor's 41 component cases are reusable by exact source hashes. The new API/host wiring has 27 unique passing mocked/JSDOM cases. After a test-only void-return correction, the affected nine API cases passed again; the other eighteen test inputs are unchanged. These counts overlap in purpose and are not added as distinct product scenarios. Full frontend TypeScript with this exact ignored source overlay passes. Initial failures are retained: decorative icon names required explicit localized aria labels; no assertion was weakened. The test cleanup return-type error and corrected run are retained too.
