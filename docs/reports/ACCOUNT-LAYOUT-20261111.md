# 我的账户分区排版

## 主目标与约束

用户要求“我的资料、我的订单、商家维护”放在上排快捷菜单；资料表单按独立区块呈现，改善单列堆叠与折叠内容难找的问题。延续前一任务的账户修复和生产交付，在同一干净独立工作树开展新批次，基线 82b9503；保留已有资料认证、身份一致性、保存字段、邮件验证与角色可见性。根工作区无关改动、此前被拒绝清理的产物均保留。

## 实现方法与范围

主 Agent 直接完成边界清晰的前端布局；沿用现有 Ant Design、图标与白底黑字红色重点，不增加依赖。账户页使用顶部快捷菜单和独立资料卡片，资料区取消地址与社交账号的折叠结构，扩大桌面内容区，手机单列清晰分组。账单和退出仍可访问；商家维护保持既有角色限制。无后端、接口或数据库迁移。使用 bobuy-rapid-production 工作流交付，使用 sub2api-agent 对最终合成账户真实截图进行 Gemini 视觉复核，所有判断由主 Agent 完成。

## 验收预算与步骤

桌面 1440×900，手机 390×844 和最窄 360×800；补充日语/英文长文字和有/无地址、社交账户状态。快捷菜单同排，手机允许文字自然换行且单项至少 44px 高；菜单、按钮热区间隔至少 6px，字形到可用内框至少 3px，同排文字视觉中心偏差不超过 min(2px,字形高度10%)。页面左右安全带手机至少 16px；区块间距桌面 24px、手机 16px，同角色按钮高至少 44px。标题、说明、内容和保存操作归属清晰，无横向溢出、遮挡、未归属控件；区块内部字段间距保持一致。

先完成实现、文案与针对性行为测试，启动现有本地 Core 和真实前端，验证导航、角色、编辑保存重读、清空地址、增删社交账号、错误重试、邮箱验证区域及键盘路径。核对 Console、网络、响应式和真实截图；Gemini 只接收合成数据截图。冻结候选后统一执行前端正式全量与构建，按精确候选完成 CI 与前端单服务发布，核对实际镜像/静态资源和生产页面。截图先看整体再看原尺寸局部，功能、几何、视觉分别记录；任何必需项缺失时保持未通过。

## 当前状态

账户布局本地功能、几何与视觉验收完成。正式前端全量 765 项全部通过；生产构建、类型和四语言检查通过。生产发布及最终生产复验待执行，旧任务的资料路由修复继续保留。

实现中补充：多区块长表单提交不完整内容时，使用 Ant Design 自带 scrollToFirstError 将首个错误字段滚动至可见位置；资料保存期间同时禁止新增社交账号，防止编辑被保存后的刷新覆盖。这两项直接服务本次分区表单可用性，不改提交载荷与权限边界。桌面地址末行把邮编与清空地址操作并排，减少单独一行操作造成的空白。

复核修正：Gemini 发现手机地址双列局促、清空按钮形似输入框、社交增删按钮层级相近，以及日语底部导航孤字换行。最终手机地址单列；清空地址放独立区块底部操作区，使用深红文本动作；移除账号使用同样的深红次要动作，添加保留边框并留足间距；手机快捷菜单图标使用共同 20px 图标行与 39px 文字槽，文字按该可用槽居中；仅账户页底部导航标签使用 10px 单行以容纳日语。灰文案 #707070，危险文字 #b42b25。最终原始截图须使用原生 PNG，先前 getScreenshot 的自动缩放 JPEG 仅作草稿。

导航实测发现纯 AGENT 点击原有客户订单链接会被既有 CUSTOMER 路由守卫重定向。最终快捷菜单及账单按现有角色显示：CUSTOMER 有订单/账单，AGENT 或 platformAdmin 有商家维护，双角色显示全部三个快捷菜单。与现有 StoreNavigation 的权限可见性保持一致；不改变路由或后端权限。纯采购员与客户均保留我的资料与退出。

原尺寸像素前检发现部分拉丁字形在输入框内偏下 1.56 至 1.88px，英文账单字形偏下 1.5px，日语退出图文组偏左 1.5px。保持原预算，输入框总内边距不变并将内容上移 1px，账单采用同样的上下内边距光学校正，退出左右内边距向右校正 1px；手机快捷菜单文字在固定文字槽内上移 1px。保留修改前 final-*.png 草稿和 control-pixels.json 原始失败数值，最终同视口覆盖照片后另存失败摘要。只量取完整可见控件，固定导航遮挡的中途滚动态控件在滚到底部状态另行量取。底部导航热区间隔在账户页固定为 6px。

## 本地验收与候选冻结

生产首次布局复验撤销整体菜单 PASS：实际采购员账号只有资料和商家两项，隐藏订单的做法未满足用户要求。最终改为角色对应的已有订单目的地：CUSTOMER 到 /client/orders，纯 AGENT 到 /admin/orders；仅平台管理员且没有客户或采购员角色时不提供无权订单目的地。采购员保留全部三个上排快捷菜单。只修正客户端目的地，不扩大任何后台权限。原有布局及其他功能证据保留，重跑受影响账户/权限测试、正式构建与精确提交 CI，并再次生产验证。首次已发布前端健康，采用仅前端向前修复，数据及后台不回滚。

原生 PNG 的最终 113 个完整可见控件量测通过，像素阈值包含可见抗锯齿边界；最初只取深色核心的检测会漏掉实际字形边缘，已修正检测方法，未放宽任何布局预算。输入框最终上下 padding 为 3.5px/4.5px，保留原总内边距并校正 0.5px；字形检查以实际结果为准。整体与原尺寸局部、113 项数值、原失败记录均见本目录证据。

Gemini Pro 高能力图片请求两次上游失败，按技能规则转到最小图片已成功的 gemini-3.8-flash-high。初评发现的问题均修复；最终评审唯一疑点是添加按钮某帧出现红色边框。真实浏览器已证实该帧是原有 Ant Design hover 强调色，dangerous=false、focus=false；移开鼠标即恢复普通描边，与错误状态无关。评审把地址输入框焦点边框推断成校验错误的说法未采纳；真正的两账号校验错误及首字段 y=397.53 至 493.53px 居中可见证据独立保留。

真实合成账户完成姓名修改保存、整页刷新和恢复；地址清空、社交移除/新增空态、两账号必填校验、邮箱空验证码校验、英文/日语窄屏、顶部订单路径与返回均完成。原纯 AGENT 角色不显示客户订单/账单；单独创建双角色本地 fixture 展示三个快捷菜单，不授予生产账户新权限。本地旧 Core 的商家仪表盘聚合接口存在 null-id 错误，导航本身到达既有授权管理路由；后台聚合修复不在本批范围，生产管理入口读取另行复验。生产不写真实用户资料。

正式全量与覆盖率命令成功：765/765，行/语句 81.85%，分支 81.82%，函数 59.56%，如实记录原有配置的实际结果，不宣称额外覆盖率阈值。类型、1610 个资源 key、生产构建和首页预渲染通过。正式 dist 在独立浏览器的 1440×900 与 390×844 实际加载，干净账户页 Console 错误为 0，入口和样式资源已绑定。
