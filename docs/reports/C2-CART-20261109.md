## Implementation and design

- `bobuy.cart.v2:guest` and `bobuy.cart.v2:user:{id}` hold a whitelisted cart and opaque revision. The old shared key is guest-only input. Loading authentication hides prior account drafts. Logout/A→B never imports another account's cart. The guest and account selections remain separate until the user chooses keep account, use guest, or compatible merge. Quantity/currency/trip/price conflicts and 99/50 limits reject a merge rather than silently summing. A persisted guest decision prevents repeated merges of the same revision; the original guest draft remains available after logout.
- Web Locks serialize local compare/write across tabs. Each write checks the expected stored revision even if a storage event is delayed. The event preserves local selection and requests an explicit choice. Replacement/reset are deliberate actions. A queued edit is invalidated by identity changes/unmount. Browsers without Web Locks get a visible save error and perform no unsafe write. This implementation stores no access/refresh credentials, email, personal profile or address in a cart; signed *public price quote tokens* remain necessary cart facts.
- Bounded sale reads and explicit price review are preserved. Quantity changes cannot silently adopt a newer quote. Cart modifications rotate requestId; unchanged retry retains it. Synchronous submit tickets block double invocation; responses are bound to identity, token, requestId and draft. Old account/token/unmounted responses cannot publish a receipt or clear a cart. Success clears only the submitted unchanged selection; later additions remain visible with an order link. Own orders/billing remount on identity changes.
- Checkout delivery UI reads/saves only the authenticated self-profile address and preserves the cart. Contact name, country/region, city and street address are required for a NEW checkout; phone/postal/geolocation are not new mandatory gates. A failed read/save blocks new submission, retains the cart and exposes retry/error. No address is placed in local cart storage.
- The server derives ownership from Authentication, locks and refreshes the user before reading current address/roles, then retains existing trip and deterministic product locks and current server pricing/eligibility. It copies delivery facts into an immutable order snapshot (format version1). Existing product identity/pricing snapshots and transaction/relationship behavior remain.
- New checkout payload SHA256 canonically binds trip, normalized currency, aggregated quantities and supplied quote revision/currency/token. Reordering/equivalent duplicate lines are stable; ambiguous duplicate quotes and quantity overflow reject. Same user/key with different accepted content rejects. A successful new retry returns the existing order before address/trip/current-quote checks, including after later profile clearing, trip closure or repricing. Historical orders with no payload hash retain the prior trip/quantity/currency retry contract and are never backfilled with invented historical delivery facts.
- Order/ledger/picking/delivery views use the order snapshot when present. Ledger responses identify `ORDER_SNAPSHOT` versus `CURRENT_PROFILE_LEGACY_FALLBACK`; the customer UI labels the latter explicitly. Customer order cards show no invented old snapshot. Existing merchant replacement retains both delivery snapshot and payload hash; customer-supplied trusted metadata remains read-only/hidden.
- Added four-language cart choices, recovery/address messages and historic-address explanations. No shared recommendation CSS, pricing language keys or business content were changed.
