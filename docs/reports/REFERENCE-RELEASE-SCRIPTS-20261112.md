# 基础档案发布脚本改进

授权和目标：用户要求确保实际发布执行遵循已采纳的轻量基础档案规则。本次仅修改发布工具、测试和文档，不重发已上线档案，不修改业务数据。

## 发现及修复

通用 `scripts/publish-production.py` 原先仅接受版本号，随后无条件切换nginx维护配置、停止应用、全表指纹、pg_dump、恢复演练及激活。`scripts/run-server-release-window.ps1` 原先完整窗口也会无条件执行整库导出和恢复演练。仅更新文字规则未能改变这两条命令链。生产服务器实际通用入口原摘要为 `655140da83732409f6ebf4970dddc0fac142bbcc15891c9685239927e9bb2f22`，仍具有旧行为。

修复为Python入口强制显式模式；基础档案走 `reference-data`，维护模式须有具体理由，并写入评估回执。基础档案计划、SQL、每张目标表的检查及真实验收绑定摘要和源码；已审查SQL与检查在单事务中执行，使用局部锁及语句超时。成功仅标记导入验收完成，应用版本和浏览器验收继续单独承担。基础档案命令链没有全量快照、全局停写、全业务表指纹、服务替换或数据库恢复；失败和连接不确定均要求检查，已有回执拒绝盲目重放。

旧PowerShell窗口在任何本地或远程命令之前检查 `-AllowFullSnapshot` 与 `-MaintenanceReason`。`-PrecheckOnly` 保留只读预检。定时备份和本地隔离迁移演练保持各自用途。历史版本绑定operator和回执保持原样，文档禁止将其直接当新发布模板。

## 发布工具安装与回滚

服务器只安装已提交的 `publish-production.py` 和 `reference_data_release.py`，依赖先安装，逐个原子替换，核对实际字节摘要。原服务器文件保存在 `/opt/bobuy/releases/20261112.reference_release_tooling.1/publish-production.before.py`，原文件摘要及源码提交、实际新文件摘要、三条无副作用CLI烟测和所有容器前后身份记录保存在 `installed.json`。有正在运行的通用发布进程或原文件摘要漂移时拒绝安装。

工具安装失败则只回退这两个脚本；不操作数据库、服务或历史发布目录。人工回滚前先核对是否有后续工具变更，再原子恢复保存的旧文件并仅移除本次新增模块；旧版本默认重型行为会随回滚恢复，须同步撤销对应执行规则或保留显式入口守卫。
