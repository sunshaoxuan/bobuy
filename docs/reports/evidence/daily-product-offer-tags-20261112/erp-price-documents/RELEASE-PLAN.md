# ERP调价单切换计划

范围为V34到V35、共享实体的core/ai/im/auth四个Java服务、Frontend和每日01:00标签SQL。网关无共享实体依赖，复用原镜像，仅在停写窗口停启。原因：V35转换业务数据并删除旧实体列，旧应用与新结构不兼容。只使用Bobuy既有数据库及依赖，其他项目、对象存储配置和数据不调整。

切换前：复用相关输入匹配的后端690项及覆盖率、来源27项、PG标签15项、迁移1项和服务Smoke，界面收敛后三组件13项及生产build通过，CodeQL三语言通过。实际PG副本迁移364条及幂等通过；最终真实页面验收见ui/scoped-acceptance.md。冻结提交、JAR、镜像、SQL、配置及operator摘要，记录当前全部运行镜像。旧timer保持禁用。先加载候选镜像及校验字节，不切应用；备份保留旧应用镜像及配置，确认可用磁盘。基线漂移则停止。

维护窗口：唯一公网入口启用现有维护配置，验证拒绝业务请求后停止全部Bobuy应用写者。获取停写后数据库指纹及完整dump，在同一PostgreSQL容器的隔离恢复库完整恢复并核对。先在恢复库应用同一V35 SQL，记录预期转换后所有业务表指纹，单头比较排除本次建账时间。删除隔离库后才升级生产Core，由Flyway执行V35；核实版本、单据/明细、原来源快照及受保护表，随后升级其余兼容Java应用及Frontend。校验所有JAR、前端资源、运行标签、健康、对象存储开关与其他项目保护状态。

安装摘要绑定的单据专用标签SQL，执行只回滚预览，再真实同步及幂等检查。任何业务改动必须对应本次单据投影和根权限变更回执，其他标记保留。通过后先持久记录OPENING_WRITES，再恢复公网入口；此阶段标记或结果不确定均禁止数据库恢复。最后启用原systemd timer，确认Asia/Tokyo每日01:00及实际下一次时间。

恢复规则：入口确定未恢复写入且停写备份完成真实恢复验证时，停止所有新应用，使用已有受控restore helper恢复停写备份并核对完整指纹，恢复原五个应用和Frontend、原配置、原标签脚本；旧timer保持暂停。入口恢复后及入口状态不确定时，隔离问题并前向修复，禁止旧dump覆盖新写入。每个阶段保存状态，现有执行记录禁止无条件重跑。

验收：实际生产版本/资源、V35结构及迁移数量、调价单只读后台接口、商品公开价格/优惠投影、标签真实运行及幂等、timer时间和旧Codex任务已删除。生产不创建客户订单或虚构促销；手工单据/批量审批/撤销等写操作使用本地明确标注的合成数据完成。
