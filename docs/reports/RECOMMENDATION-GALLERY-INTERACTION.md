# Recommendation gallery gestures and localized names

Scope: fix inline/fullscreen recommendation gallery gestures and put the Japanese original on a separate semantic name line. No image, business content, sale, inventory, permission or credential changes. Reuse the existing shared local frontend and real public read-only image/data requests. Preserve the current card gradient/radius.

## Cause and implementation

Production 20261026.5 used a standalone Ant Design Image preview for the selected detail image, plus separate thumbnail buttons. It had no horizontal swipe navigation or unified gallery gesture state. Read-only touch reproduction on real item 1 (two official images) confirmed unchanged image URL after horizontal swipe and an attached default “preview” mask. The transient mask opacity at screenshot sampling is recorded rather than claiming it stayed visible.

Replace that Image preview with a focused recommendation image viewer: inline horizontal swipes change images, vertical movement remains native drawer scrolling, and deliberate taps/Enter open fullscreen. Movement suppresses subsequent click activation. In fullscreen, fit swipes navigate; native-size drags only pan and clamp to actual image bounds. Double tap (touch) / double click (mouse) toggles native 100% and fit; explicit controls provide the same action. Each image change resets fit/pan. Counter, disabled edge navigation, thumbnails, close/Escape, arrow keys and 0/1 fit/native shortcuts are included. The existing Modal supplies focus containment and background scroll locking; closing restores the inline focus. No hover preview overlay or original image modification is used.

Localized display names keep the existing combined accessible name but render the translated name and Japanese original in separate span elements. Parentheses stay with the Japanese text. Original data contains no inserted newline. Japanese or missing-translation fallback displays only one name line. Lists and item detail use the same name component. A later user clarification also removes ellipsis from issue-directory titles and the old three-line product-name clamp; article headings explicitly wrap without clipping. Candidate b470333 / successful CI 40370154022 was superseded before activation for this additional CSS requirement; its application checks remain relevant to unchanged gesture code, while the final exact-head release still requires its own CI.

## Product profile finding / shortest normal UI path

This is already implemented independently of sale review: RecommendationService.upload and editItem call RecommendationCatalogService.ensure. Newly saved items create private DRAFTER_ONLY / PRE_ORDER profiles with REQUIRES_REVIEW pricing; reference prices do not become actual sales or inventory. Identity is scoped by owner, source issue, exact item code and reviewed name, keeping warehouse/online issue quotations separate. Existing explicit product links are reused without replacing prices/stock. No automatic supplier+ITEM cross-issue merge is added because it could combine distinct offers or uncertain identities.

The two legacy posts were registered before automatic profile creation. The previous accepted snapshot had 152 items but zero product records. The admin product query filters merchant ownership, not DRAFTER_ONLY visibility; therefore the empty products were not caused by hiding private profiles. During this task the parent completed normal visible UI backfill: all 152 recommendations now link to 142 private, unpriced profiles (30 online + 112 warehouse new profiles, 10 same-specification explicit reuses). Do not repeat this operation; preserve the latest pre-deploy state.

Normal visible UI for future missing links: open `/admin/recommendations?post=<id>`, scroll to “product profiles / bulk listing” (RecommendationCatalog), choose the “build missing profiles” button and confirm, then follow its `/admin/stock-master` link. The button submits only currently missing recommendation IDs, version-checks the post and reuses deterministic profile identities; it does not publish/price products. Existing product selection/link is also available per row. Parent UI worker owns real content writes; this engineering task does not run them. New recommendation item saves already build/associate profiles, so no duplicate server mechanism is needed.
