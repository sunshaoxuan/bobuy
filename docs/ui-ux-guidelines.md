# Bobuy UI/UX 开发标准

面向所有会改到用户界面的任务。功能和美观都是验收项，缺一不可。本标准以 **2026-11-14 已上线站点（`main`，含 #94）的真实实现** 为准，token 与数值均从当前前端代码提取。历史规划若与现行代码冲突，以本标准与现行 CSS 为准。

相关文档：`docs/guides/GUIDE-08-i18n规范.md`、`docs/design/STOREFRONT-PINTEREST.md`。

## 1. 原则
1. **先复用，再新做。** 优先使用页面已有控件、class 与 token。
2. **禁止原生未样式化控件。** checkbox、radio、select、button 必须有完整视觉状态。
3. **与邻居齐高对齐。** 同组控件的高度、圆角和间距必须一致。
4. 公开商城 `.storefront` 与工作台 `.app-shell` / `.merchant-shell` 是两套表面，不得混用；商城不可使用后台 Ant Design `Switch`。
5. 当前没有暗色模式，不得擅自增加。
6. 新动效须尊重 `prefers-reduced-motion`。
7. **导航只呈现可用且唯一的入口。** 未完成功能必须通过默认关闭的功能开关隐藏，不得在导航中展示空壳或「暂未开放」占位；同一功能不得提供重复入口。以图片为主的目录页必须使用可收缩且不推动内容布局的导航，把宽度让给商品；收缩控件与记忆状态仍须符合本文件的可访问性与双视口验收要求。品牌 Logo / 页眉不得因导航收起而隐藏；可收缩导航必须放在与品牌页眉分开的容器中，只收起导航菜单项。

## 2. 已落地 token
### 2.1 工作台全局
`--zen-bg: #faf9f6`；`--zen-ink: #2d2926`；`--zen-muted: rgba(45, 41, 38, 0.58)`；`--zen-line: 0.5px solid rgba(0, 0, 0, 0.08)`；空间为 `0.5rem / 1rem / 1.5rem`；`--blur-glass: 10px`；玻璃不透明度为 `0.9 / 0.82 / 0.72`；投影为 `none`。字体为 `Inter`, `Segoe UI`, system-ui, sans-serif。

### 2.2 公开商城
强调色 `#d93630`，hover `#ce3028`；背景 `#fff`；主文字 `#232323 / #191919 / #242424 / #282828`；辅助文字 `#626262 / #666 / #777 / #555`；浅底 `#f3f3f3 / #f5f5f5 / #f0f0ed / #f7f7f7`；选中深底 `#242424 / #252525 / #171717`；边框 `#d9d9d9 / #ededed / #eee / #00000010`。默认字号 **15px**，行高 **1.65**。

### 2.3 圆角家族
已有 **6px**、**8px**、**16–20px**、**24px**、**26–28px / 999px**。同组使用同档。好物推荐排序和分类胶囊均为 **8px**；公开列表的状态 / 提示消息使用 **26–28px / 999px** 大圆角档，见 §3.7，不得套用 **6px** 按钮档。

### 2.4 断点与验收视口
主移动断点 **`max-width: 767px`**；另有 `375px`、`650px`、`1023px`、`1099px`、`1199px`。至少在 **390×844** 与 **1280×800**（或 1280×900）截图自检。

## 3. 控件规范
所有可点击控件最小高度 / 触控目标 **≥ 44px**。

### 3.1 按钮
商城主按钮 `#d93630`，hover `#ce3028`；后台主按钮 `#252529`，hover `#45454c`。砖红色不得用于筛选芯片。

密集桌面管理表 / 工具条中的 icon-only 圆形按钮是 ≥44px 规则的有限例外：视觉直径 28–32px，且计算宽度与高度必须相等；全局 `min-height: 44px` 不得把可见圆拉成长圆。命中区不得小于视觉尺寸并建议扩至 36–40px；需要扩大时只能使用透明伪元素或包装层，不得拉伸可见按钮。按钮必须有 Tooltip（hover / focus）、`aria-label` 和完整交互态。手机、触控及非密集控件仍须 ≥44px，并复用 `--zen-ink`、`--zen-muted`、`--zen-line`、`--zen-bg` 等工作台 token。

### 3.2 搜索
`.browse-search` 最小高度 48px、圆角约 28px、填充 `#f0f0ed`、无边框，不得套到短筛选控件。

### 3.3 选择器
`.product-sort` 高度 44px，最小宽 200px，边框 `1px solid #d9d9d9`，圆角 **8px**，白底，文字 `#282828`，字号 14px，内边距 `8px 30px 8px 12px`；焦点 `outline: 2px solid #795908; outline-offset: 2px`；≤375px 拉满。

### 3.4 分类胶囊 / 筛选芯片
容器 gap 8–9px；未选中 `#f3f3f3` / `#f5f6f5`、文字 `#303846`；选中 `#242424` / `#252525`、白字；内边距 `10px 16px` / `10px 18px`；最小高 44px；字号 14px、字重 500。好物推荐页用 **8px** 圆角。

### 3.5 开关与布尔筛选
Ant Design `Switch` 只用于后台。公开商城布尔筛选使用 `button` + `aria-pressed`（或视觉隐藏 input + 已设计 label），不得使用浏览器默认 checkbox。

### 3.6 控件组 / 过滤栏（必须遵守）
使用 `display:flex; align-items:center; flex-wrap:wrap` 与已有 gap；同组齐高；窄屏换行且不撑出视口；未选中浅灰、选中深底白字；排序旁焦点优先用 `2px solid #795908`；hover 仅用于精细指针；禁用态仍保持 44px 命中区。

好物推荐页 `.catalog-sort-controls` 用 `margin-left:auto` 将排序与标记优先控件作为整组右对齐，组内 `justify-content:flex-end`，并清除内部 `.product-sort` 的自动左外边距；保留排序在前、标记优先在后的 DOM 顺序与窄屏自然换行。

### 3.7 状态 / 提示消息（消息标签）
1. 列表底部的「加载更多」、加载中，以及将来若增加的列表结束提示，属于状态 / 提示消息，不是购买、提交等主操作按钮。
2. 必须使用 **26–28px 或 `999px`** 大圆角 pill / capsule 消息标签；禁止使用 **6px** 小圆角按钮样式。`.feed-loader button` 按本条实现，不得出现 Ant Design default button 的浅阴影、小圆角描边或其他按钮 chrome。公开商城已有 `.storefront .ant-btn { border-radius: 6px; padding: 7px 14px; }`；新样式选择器必须比它特异度更高（例如 `.storefront .feed-loader .ant-btn`），避免圆角和内边距被盖回按钮形态。
3. 标签水平居中，使用公开商城既有浅底（`#f3f3f3` / `#f5f5f5` / `#f7f7f7`）和辅助文字色（`#626262` / `#666` / `#555` / `#444`），边框应无或更轻，不得用砖红 `#d93630` 填充；沿用 `.feed-loader` 的 `padding: 24px 0` 或相近节奏。它须与购买 / 提交主按钮，以及 **8px**、选中深底白字的筛选芯片有明确视觉区分。
4. 自动加载列表可保留 `button`（或等价可达控件）作为键盘 / 点击的手动兜底，但命中区须 ≥44px，并完整提供 `:focus-visible`、hover（仅精细指针）、active、disabled、loading 状态；所有状态均保持大圆角消息标签形态，禁用或加载时不得退回默认灰按钮。焦点环应与公开商城既有焦点协调，不得伪装成主按钮描边。
5. 本条不强制改变分页行为：当前 `hasNext === false` 时卸载控件且不展示结束文案；将来若增加列表结束提示，也必须沿用本条视觉语言。
6. 新增或调整 UI 模式时，必须把实际落地做法写回本标准。
7. 顾客端页面的状态卡或信息卡没有真实内容可展示时（例如「暂无…」），必须连同容器与间距整块不渲染，不得留下空占位。仅当该空状态是当前页面的主内容，且同时提供明确的下一步操作时，才可展示。

## 4. 状态、无障碍与动效
控件须有默认、hover、`:focus-visible`、active、disabled（如适用）；不得无替代地移除 outline。须有可见标签或 `aria-label`；布尔芯片用 `aria-pressed`；保证键盘可达、对比度足够、焦点不被裁切。

## 5. 文案与 i18n

商城商品目录使用「好物推荐 / 好物推薦 / Product Picks / おすすめ商品」；期次入口使用「活动邮报 / 活動郵報 / Campaign Newsletter / キャンペーン便り」，默认关闭的既有功能开关控制其入口。所有视口的唯一账户导航入口均为右上角 `/account` 图标，手机 ≤767px 也须保持可见，底部快捷栏、侧栏与抽屉不重复提供。

用户可见文案走 `zh-CN`、`zh-TW`、`en-US`、`ja-JP` 四语资源。按最长译名设计：「标记商品优先」「標記商品優先」「Marked products first」「マーカー付き商品を優先」。不得溢出、重叠或随意截断。

### 6.1 系统 / 错误 / 维护页
- 系统更新页属于公开商城表面，而非工作台：沿用 `#f7f8f4` 背景、`#c74036` 品牌标识、大圆角内容卡片，以及默认、hover、focus-visible、active 完整的 ≥44px 重试按钮。
- 边缘代理必须提供内联 CSS/JS 的自包含四语页面；frontend 或 Java 容器停止时仍可显示。应用已加载后则复用 `MaintenanceNotice`，两者都提供手动重试与 20 秒自动重试、保留原 URL，并尊重 reduced motion。
- HTML 文档使用 503、`Retry-After`、no-cache/no-store 与 noindex；API 使用 JSON 503，绝不返回维护 HTML。合法的鉴权、权限或 CSRF 401/403 不得被维护状态拦截。
- 维护页表达全页系统状态，不是 §3.7 所述列表底部状态/提示消息；恢复后应回到原页面，并保留本地购物车。
- 新增或调整此模式时，须把已经通过 390px、1280px 截图与计算样式（尤其 `.storefront .ant-btn` 覆盖）验收的实现写回本节。

## 7. Codex / 开发者自检清单
- [ ] 复用 token / class / 组件，无新主色、圆角体系或未样式化控件。
- [ ] 同组齐高、间距一致、圆角同档。
- [ ] 默认 / hover / focus-visible / active（及 disabled）完整。
- [ ] 触控目标 ≥44px，标签、键盘操作和对比度完整。
- [ ] 四语文案在 390px 不溢出。
- [ ] 在 390px 和 1280px 截图；栈不可用时如实说明。
- [ ] 窄屏无横向滚动、重叠；reduced motion 未破坏；未扩大范围。

## 7.1 紧凑 / 密集表
- 桌面行计算高度约 56–72px；每行使用 40–48px 小缩略图，无图时显示可访问的占位图。
- 文本最多两行省略，并须可通过 hover / keyboard focus 的 Tooltip 查看全文。操作列使用不换行的圆形 icon-only 按钮簇并始终可见；窄桌面应隐藏价格、库存、状态等低优先级列，不得让 sticky 操作列遮挡可见列。
- 本页落地为 `.stock-compact-table` 64px 行、`.stock-compact-thumb` 44px、桌面 `.stock-compact-action` 32×32px；≤767px 为 44×44px。两种尺寸的可见按钮都必须是计算宽高相等的正圆，不得被工作台全局 44px `min-width` / `min-height` 拉伸。
- 至少在 1280×800、1024×800、390×844 实拍，并按 §9 核对行、缩略图、按钮的尺寸、圆角、背景与阴影。

## 9. 计算样式与截图验收
1. UI 验收不得只做静态源码审查。必须使用 Playwright 或等价浏览器自动化，在 **390×844** 与 **1280×800** 视口实拍改动区域，并核对目标控件的计算样式；至少记录 `width`、`height`、`min-width`、`min-height`、`border-radius`、`border-color` / `border-width`、`background-color` 与 `box-shadow`。圆形控件还必须明确核对计算宽高比为 `width === height`。
2. 验收以浏览器计算结果为准：即使源码声明了 `border-radius: 999px`，只要计算值不符合设计要求，也必须判定为失败。
3. 公开商城的 `.storefront .ant-btn` 会把圆角和内边距覆盖回 **6px** 按钮形态。为 `.ant-btn` 或 `.feed-loader .ant-btn` 增加样式时，选择器特异度必须高于它（例如 `.storefront .feed-loader .ant-btn`），并同时检查背景、边框和阴影未恢复为默认按钮 chrome。
4. 新增或调整 UI 模式时，必须将已经落地并通过上述实拍与计算样式验收的做法写回本标准。
5. 导航开关只控制入口可见性，不决定默认路由：`/` 始终落到「好物推荐」`/products` 并完整保留查询字符串；被开关隐藏的活动邮报仅保留直接 URL 访问。账户在所有视口只保留一个指向 `/account` 的顶栏图标入口；移动底栏、侧栏和抽屉不得重复账户入口。顶栏图标须具备本节要求的 44px 触控目标、键盘焦点与本地化 `aria-label`。

## 10. 禁用提交须说明缺项
提交按钮因校验或业务前置条件禁用时，必须在按钮附近持续显示可操作的缺项说明（例如金额、单位、原因、确认勾选、履约方式或启用状态），并随输入即时更新。不得只依赖 tooltip、颜色或隐藏条件；表单满足全部可见条件后按钮必须可用。服务端失败仍须显示可理解的错误，并回滚任何乐观界面状态。

## 3.8 系统可推导字段
- 可由已存来源或已录入字段唯一计算的校验和、规范化编码、来源 SHA-256 等，必须由系统计算并以只读证据样式回填，不得作为手工必填项。
- 标签旁须以简短说明或 Tooltip 写清算法、输入字节和规范化口径。
- 仅当来源缺失且系统无法计算时才允许手工输入；界面须说明原因并执行完整格式校验。
- 来源不变时不得清空自动值；来源变化时须重新计算，并撤销操作者的确认状态。
- 期次来源审核复用 `RecommendationIssueDateEditor.tsx`、Ant Design `Input` / `Tooltip` / `Alert` 以及相邻只读证据的 token。

## 3.9 表单输入与校验态
- 校验状态必须反映当前值。错误描边和错误文案只用于真实错误，并仅在对应字段已经交互或尝试提交后出现；未触碰的空白初始态不得预先标红。值变为合法后须立即清除错误态，且不得继续显示“请先填写”等已经过时的提示。
- `:focus-visible` 与错误态必须可区分；工作台输入优先使用 `2px solid #795908`、`outline-offset: 2px` 的焦点环，错误色只表达真实校验失败。
- 在主移动断点 `max-width: 767px` 及粗指针环境，表单单行文本输入（包括 `type="date"`）的计算高度和 `min-height` 均须 ≥44px，并与同组控件齐高、同圆角档、间距统一。
- 期次来源审核的落地验收须在 390×844 与 1280×800 实拍，并按 §9 记录日期、来源引用、手工哈希及“?”帮助按钮的计算样式；移动端三个输入须 ≥44px，“?”命中区须为计算宽高相等的 44×44px，且窄屏不得横向溢出。

## 11. 操作失败与确认状态

- 发布、保存等操作若有多个校验失败条件，服务端须返回稳定条件码，界面须在对应操作附近逐条展示具体缺项与修复方法；可定位的字段应提供键盘可用、触控目标 ≥44px 的跳转或编辑入口。不得把商品主档待审核、来源上下文、四语或图片缺项合并误报为标题正文缺失。
- 请求失败不得静默清除开关、核对勾选或用户输入。只有对应输入或其证据版本实际变化、用户主动撤销，或成功操作已使该确认不再适用时，才可明确更新确认状态。
- 缺项容器与操作按钮须复用所在页面 token、圆角和交互态；长的四语说明在 390px 下换行，不得横向溢出。按 §8 / §9 在 390×844 与 1280×800 实拍并记录计算样式。

## 13. 批量修复与 AI 建议

- 批量修复必须先展示将变更的对象和字段，经操作者明确确认后才保存；取消不得写入。无法自动完成的字段必须保持空白、展示原因，并保留手工编辑入口。默认只补空白值，覆盖已有值必须由操作者另行选择。
- AI 生成文案必须明确标注「AI 建议」，并在写入前保持可审阅、可编辑。未确认的建议不得保存或公开，也不得与已确认的人工内容或主档内容混淆；生成失败时保留空白并显示错误。
- 批量、建议和缺项操作在 390px 下必须单列且无横向溢出，主要操作触控高度至少 44px；正在处理的商品卡在空间不足时铺满网格。

## 14. 面向使用者的合并建议（可由后续 issue 引用）
