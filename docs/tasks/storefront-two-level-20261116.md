## 冻结候选的实现与发布说明
- 唯一配置：`backend/src/main/resources/shopping-categories.json`。顺序即展示顺序，四语短名、图标与两级关系集中维护。规则示例：`{"nodeId":"实际稳定节点ID","categoryId":"shop-drinks-juice","subtree":true}`。明确的商品例外使用 productId；不按名称或旧标签猜分类，不从用户旧CSV自动导入。
- 商品有主路径时以该节点匹配；subtree 包括节点自身与后代，覆盖父节点直挂。多个互不重叠的来源规则可指向同一二级。重名不参与匹配。显式商品例外覆盖来源规则后只有一个归属。未映射商品保留可见性并进入明确的未归类集合；发布核对脚本遇任何未映射返回非零，禁止以此代替完整映射交付。
- `/api/storefront/product-browse` 保留分页、查询、报价和版本校验，增加 facet parentId/icon、shelves 与 selectedCategory。货架从同一排序结果选前8件；二级网格取同集合。计数基于原公开投影，隐藏商品不会因为映射被暴露。
- URL 使用单一 `category=shop-…` 表示一级或二级；父级可由配置唯一恢复，避免两个查询字段矛盾。关键词、排序、商户范围继续保留。旧原始分类链接归总览；新前端拒绝将非shop-身份显示成购物目录。
- `/products` 与 `/recommendations` 根路径共用目录。`/recommendations/:id` 和旧 `?item=` 仍走原详情路径；`?product=` 保持现有详情。返回按钮明确指向父分类，浏览器返回仍沿历史恢复位置。
- 无数据库迁移，无商品、价格、库存、可见性、来源路径或推荐数据写入，无 provider/认证变更。配置随应用版本交付。发布前必须填入真实规则、通过全主档与公开子集核对；后端先兼容上线再更新前端。应用回退用原兼容版本，无数据库回滚需求。当前不能执行此发布。
- 既有PR门禁按当前 `.github/workflows/pr-check.yml` 执行（它与旧README删除CI的历史描述不同），另有CodeQL；只跟踪实际产生的运行，不在本地重复全量。
