## 最终运营文件契约

| 列名 | 必填 | 规则 |
| --- | --- | --- |
| `SKU` 或 `商品编号` | 是 | 商品 `itemNumber` 的逐字精确值；必须在当前商户内唯一（平台管理员范围内也必须唯一）。 |
| `Costco breadcrumb`、`官网面包屑路径` 或 `分类路径` | 是 | 运营提供的日文路径，以全角 `＞` 分隔；每段非空且逐字匹配，不修正、不模糊匹配、不自动翻译。 |
| `备注`、`标记`、`Note` 或 `Flag` | 否 | 第三列；英文表头不区分大小写。标记原文保存在逐行审计，已匹配行在确认时保存到商品 `category_import_flag`。 |

首行必须为以上两个必填列，可追加第三标记列，顺序固定，中文与英文别名可组合使用；文件扩展名为 `.csv`（UTF-8，可带 BOM）或 `.xlsx`，读取首个
工作表。空白首行不跳过，未知表头拒绝，列数不符的行保留原文并退回。三列 CSV 的空标记保留末尾逗号，XLSX 允许空第三单元格。额外列不会静默丢弃。导入页提供「下载 CSV 模板」，包含中文表头及三条合成示例，须由运营替换为真实资料。示例：

```csv
商品编号,官网面包屑路径,备注
FIXTURE-0001,食品・飲料＞野菜・果物,推定
FIXTURE-0002,食品・飲料＞野菜・果物,最接近路径
FIXTURE-0003,食品・飲料＞野菜・果物,待核
```

分类节点的 `ja-JP` 保存运营提供的日文名称；在没有运营审核译名时，zh-CN、zh-TW、en-US
同样显示日文原名，遵守 `docs/category-tree-data-model.md`，不产生机器翻译。仓库商品若
官网无页面，也必须由运营在文件中明确给出路径，系统不猜测。

### 可选标记的逐行规则

- `推定`：按提供路径正常匹配和导入，表示没有官网面包屑依据。原文记录在预览、审计及确认后的商品上。
- `最接近路径`、`closest path` 或运营自己的仓库商品标记：正常导入并保存原文，保留与 `推定` 的区别，不自动改写或映射标记。
- 标记去除首尾 Unicode 空白后**精确等于 `待核`**：身份未确认，始终未匹配，出现在预览及退回 CSV 中，不新建路径、不分配分类、不修改该商品既有归属或标记。`待核x`、`待 核` 等其他文本不猜测为待核，原文保存。
- 未提供或空白标记不会清除商品已有标记。非空标记代表本次运营提供的值，确认后覆盖商品当前标记，历史各次值保留在审计。预览不修改商品。
- 同商品的不同路径或不同原始标记构成冲突，相关匹配行全部退回；相同路径、相同标记的重复行允许且结果幂等。同商品在文件中出现 `待核`，即使该行路径无效，也阻止文件内其他别名行给它分类。

预览和确认结果包含原始 `flag`；审计 API 同样返回它。退回 CSV 包含 SKU、原始路径、Flag 和原因，错误引号或额外列保留原始记录。商品标记为持久化可查询字段，供后续筛选使用，本批不增加筛选页面。V42 幂等增加两个标记字段及排序来源字段，不写入任何真实分类数据。

## 行为与保护

预览会为每一行给出“已匹配”或“未匹配/未知 SKU”及原因，并计算确认时才会创建的
节点。未知、空值、歧义 SKU 和无效路径都保留在预览与可导出的未匹配清单中。确认只
处理预览中唯一匹配的行；相同日文名只在相同父节点下复用，节点使用独立稳定身份。
确认与树管理共用永久系统行的事务写锁，逐级精确查找并复用节点，商品主路径以商品 ID 唯一，因此重复确认和重新导入同一路径均幂等。独立身份避免节点移动后重新导入旧路径覆盖已移动节点。

审计记录操作者、时间、原文件名与 SHA-256、预览/确认状态、匹配/新节点/未匹配数量，
并保存导入前后商品总数。确认事务若发现总数变化会整体失败；对
`bb_product` 仅定向更新 `category_import_flag`，价格、库存、公开状态与推荐数据不在写集合内。
