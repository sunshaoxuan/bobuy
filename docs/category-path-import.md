# SKU → Costco 面包屑路径批量导入（issue #129 / child 2）

## 本批授权范围

本批在商户/平台管理工作台增加 CSV/XLSX dry-run、逐行结果预览、显式确认、未匹配
CSV 导出和导入审计。它只写入分类树节点和商品唯一主路径；不修改商品价格、库存、
公开状态、推荐期次或商品主档行，也不抓取 `costco.co.jp`，不包含真实生产运营清单。

功能与美观同时验收，须符合 `docs/ui-ux-guidelines.md`：
- 功能按本 issue 需求逐条通过，不改变未授权行为。
- 视觉复用工作台 token 与 Ant Design 组件；控件具备焦点/禁用态、触控目标至少 44px。
- zh-CN、zh-TW、en-US、ja-JP 长文案在 390px 下换行且不横向溢出。
- PR 附 390×844 与 1280×800 的预览和确认关键状态截图。
- 仅运行本批后端导入与前端导入页的最小测试及 PR checks。

## 最终运营文件契约

| 列名 | 必填 | 规则 |
| --- | --- | --- |
| `SKU` | 是 | 商品 `itemNumber` 的逐字精确值；必须在当前商户内唯一（平台管理员范围内也必须唯一）。 |
| `Costco breadcrumb` | 是 | 日文官方分类名，以全角 `＞` 分隔；每段非空且逐字匹配，不修正、不模糊匹配、不自动翻译。 |

首行为以上两个英文列名，顺序固定；文件扩展名为 `.csv`（UTF-8）或 `.xlsx`，读取首个
工作表。示例（仅为合成夹具，不是生产清单）：

```csv
SKU,Costco breadcrumb
FIXTURE-0001,食品・飲料＞野菜・果物
```

分类节点的 `ja-JP` 保存日文官方名称；在没有运营审核译名时，zh-CN、zh-TW、en-US
同样显示日文原名，遵守 `docs/category-tree-data-model.md`，不产生机器翻译。仓库商品若
官网无页面，也必须由运营在文件中明确给出路径，系统不猜测。

## 行为与保护

预览会为每一行给出“已匹配”或“未匹配/未知 SKU”及原因，并计算确认时才会创建的
节点。未知、空值、歧义 SKU 和无效路径都保留在预览与可导出的未匹配清单中。确认只
处理预览中唯一匹配的行；相同日文名只在相同父节点下复用，节点 ID 由完整路径稳定
生成，商品主路径以商品 ID 唯一，因此重复确认和重新导入同一路径均幂等。

审计记录操作者、时间、原文件名与 SHA-256、预览/确认状态、匹配/新节点/未匹配数量，
并保存导入前后商品总数。确认事务若发现总数变化会整体失败；写入代码不保存
`bb_product`，因此价格、库存、公开状态与推荐数据不在写集合内。
