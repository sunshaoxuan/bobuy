# SKU 分类路径导入契约

以 [Parker 2026-11-15 晚间定稿](https://github.com/sunshaoxuan/bobuy/issues/133#issuecomment-6892119516) 为准，执行与验收沿用 [当前任务记录](category-tree-management.md)。保留树管理、主档选择器、权限、商品数默认排序和管理员显式顺序。本 PR 不执行生产导入、提交或推送，不改首页、#134 浏览或 #155 旧分类删除。

## 文件格式

CSV 使用 UTF-8（允许 BOM）；XLSX 读取首个工作表。首行必须是表头，前两列顺序固定，之后可有来源与备注列，每种最多一次。未知、重复表头拒绝。数据列数错误和引号错误保留原记录并退回。

| 列 | 允许表头 | 约定 |
| --- | --- | --- |
| 1 | `SKU`、`商品编号` | 精确匹配授权范围的商品编号，必须唯一 |
| 2 | `costco分类路径`、`Costco breadcrumb`、`官网面包屑路径`、`分类路径` | 接受半角 `>`、全角 `＞`，可混用；每段非空 |
| 可选 | `路径来源` | 存在此列时，每行必须使用以下三档之一 |
| 可选 | `备注`、`标记`、`Note`、`Flag` | 英文别名不区分大小写，原文保存，可与来源并存 |

三档来源：`官网面包屑（原文）`、`推定（官网无可用面包屑）`、`推定（官网无页面）`。

三档均按提供路径导入，不推导更优节点、不改写日文、空格或字符。分隔符用于拆分层级，原始路径及来源留在预览、确认和审计。旧的两列与备注格式继续支持，沿用分段边界空白清理规则；新增来源列的文件逐字保留分段内容。

45883、1731065 与其他商品采用相同逻辑，没有 SKU 特判。正式清单预期没有待核行；只有备注字面仍为 `待核` 的异常行才退回，并阻断同商品别名行。来源列的 `待核` 属于非法来源。

同商品的路径、备注或来源冲突时全部退回；相同内容允许重复。当前没有路径自动调整逻辑。今后如提出调整，必须先给运营逐条展示 **SKU、原路径、新路径** 并获得确认，禁止静默采用。

下载模板为四列，以下全部为合成示例，须替换为运营数据：

```csv
SKU,costco分类路径,路径来源,备注
FIXTURE-0001,例示親＞例示子,官网面包屑（原文）,合成示例
FIXTURE-0002,例示親>例示子,推定（官网无可用面包屑）,合成示例
FIXTURE-0003,例示親＞例示子,推定（官网无页面）,合成示例
```

## 推迟或排除名单

后台四语提供「推迟或排除的商品编号」文本框，初始值为 C 组九件：

```text
29267,1012891,55719,535557,553363,14116,14110,76838,517611
```

用逗号（含中文逗号）、空白或换行分隔。字段**替换**默认名单，追加排除项时保留所需默认编号；清空表示全部参与预览。接口为 `POST /api/category-path-import/preview` 的 multipart 参数 `deferredSkus`：缺省使用默认九件，显式空字符串表示空名单。确认使用已保存的逐行结果；修改输入或文件会撤销预览与确认勾选。

延期行单独计数并显示「已推迟」，包含在未匹配/延期导出文件中。同商品 ID 的别名也推迟，即使被排除 SKU 未出现在文件中。确认只处理已匹配行，延期商品的主路径、旧分类、备注、来源、价格、库存和公开状态保持原样。其余 454 件能否导入，以实际 CSV 预览为准；当前仓库没有该文件，无法确认真实数量或内容。

## 审计与保护

预览保存操作者、时间、文件名、SHA-256、每行原文、商品身份、结果、原因、备注及来源，不写商品或树。确认与树管理共用树锁，事务内复用相同父节点下精确日文节点，保存商品唯一主路径；重复确认不写入。

来源独立保存到行审计 `source_tier` 和商品 `category_path_source`，供后续筛选；备注继续使用 `category_import_flag`。无来源列的旧文件重新归类时清空当前来源，避免旧来源错误描述新路径；历史来源仍留审计。空备注保留旧备注。V43 幂等新增两个字段，与旧应用兼容；不重写业务数据。回退应用时保留字段与审计。

导出包含 SKU、原路径、路径来源、Flag、Reason，覆盖未匹配和延期行。商品总数校验保留，价格、库存、公开状态、推荐期次没有更新语句。

## 名称文件与运营审核

待审文件：[`ops-reviewed-names.json`](../backend/src/main/resources/category-names/ops-reviewed-names.json)。当前 `entries` 为空、`sourceSha256` 为空、状态为 `pending_ops_review`，`pendingReview` 明确列出等待运营 CSV 的工作。没有真实或猜测的 Costco 分类。

收到 CSV 后，从每条路径的每个前缀生成条目，以**完整日文分段数组**区分同名节点，记录实际 CSV SHA-256 并补齐待审列表。以下仅为格式示意：

```json
{
  "japanesePath": ["例示親", "例示子"],
  "status": "pending_ops_review",
  "names": {"zh-CN": "", "zh-TW": "", "en-US": ""},
  "reviewedBy": "",
  "reviewedAt": ""
}
```

运营审核后填写三语译名、审核人业务署名及 ISO 日期 YYYY-MM-DD，改为 `reviewed`。加载器只消费审核完整条目，拒绝重复路径、缺少来源哈希、缺失译名/审核凭据及覆盖日文原名的记录。待审条目的译名不会发布。根级 `reviewed` 仅用于全部审核完成且待审列表为空的文件。

资源随应用载入，更新文件需走后续审核与正常发布。导入确认按完整日文路径消费审核映射，为新节点和本次匹配的既有节点写入译名；待审核节点保留日文档案身份。该流程不单独启动分类发布或生产导入。

商城分类树使用审核后的简体中文，`ja-JP` 使用日文原名；后台保留日文参考及各语种审核译名。商城名称解析契约 `storefrontCategoryName` 在缺简体译名时返回空值，禁止把日文冒充中文。本批不接入或改变 `/products` 浏览；#134 接入新树时遵守此契约并等待完整译名审核。
