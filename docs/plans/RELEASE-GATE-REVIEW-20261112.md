# 测试与发布门禁重审

## 目标与授权
用户要求主 Agent 亲自重审全部测试、发布门禁及耗时过程，清除无合理依据的阻塞与浪费。本次禁止 Sub2API 与外部模型。依据仓库实际入口、历史和运行证据判断，不推断恶意或用户知情程度。

## 范围与方法
审查四个 CI 工作流、Maven 与 npm 生命周期、测试配置、Git hooks、构建脚本、发布器、迁移与恢复脚本，以及约束上述入口的正式文档。历史一次性脚本按是否仍被调用分类。保留现场已有产品改动，不发布产品、不访问客户数据、不运行真实 AI 请求、不重启共享服务。

先盘点调用关系、来源与耗时证据，再将明确重复、失效或错误耦合的步骤合批修正。必要安全、权限、迁移和恢复约束逐项解释。变更只针对门禁与其文档和回归测试。完成廉价检查后冻结候选，统一验证受影响入口，复用已有有效结果。

## 完成标准
1. 所有当前测试和发布入口有分类、证据、保留或修改理由。
2. 来源追溯区分提交历史与未提交现场，未知耗时明确标注。
3. 每项调整有可执行验证，检查继续能拒绝相关真实错误。
4. 形成审查报告，记录实际结果、剩余限制与未验证的远端配置。
