# PLAN-59: 手机优先公开商城与商客激活

日期：2026-10-22
状态：本地核心范围完成，生产发布不在本轮范围

## 1. 主目标与范围

本地实现手机优先、平板其次、桌面适配的公开客户商城；访客浏览行程和商品并使用临时购物车，在结账时注册或登录。商家维护统一位于 /admin。试点单商家，数据与权限按多商家隔离。

注册使用用户名、密码和邮箱；邮箱验证码验证属于账户全局身份事实。未验证账户可登录、浏览和提交待确认订单。商家根据归属自己的订单手工认可客户，仅激活该商客关系，不得改变邮箱验证状态或其他商家的关系。管理员的激活也必须明确商家范围。后续商家自助注册为架构预留，本轮不开放自助商家提权。

仅使用固定 Compose 项目 bobuy-local 创建一个本地测试环境；所有应用依赖属于同一项目，数据及网络由该项目管理。已存在其他项目保持不变，不执行全局清理，不触碰生产节点。

## 2. 方法与步骤

1. 核对现有认证、路由、订单与商家数据及迁移；确定最小可用端到端实现。
2. 获取高级实现建议，由主 Agent 决定商家归属、激活权限与 migration 方案；不传递秘密。
3. 更新需求，增加版本化迁移、公开只读 API、注册和验证码、商客关系及订单权限；沿用现有依赖和测试方式。
4. 实现公开首页、临时购物车、结账认证、/admin 商家入口和手机优先适配。
5. 在单一 Compose 环境运行真实 API 与邮件测试收件箱，执行单元、集成、浏览器及隔离负例。
6. 获取真实截图并作 Gemini 视觉复核，由主 Agent 验收，提交本次变更。

## 3. 完成标准

- 无登录打开 / 即可查看真实行程与商品，购物车刷新保留；结账注册后保留购物意图。
- 邮箱验证码单次使用、过期及错误尝试受控，验证码和密码不进入日志或仓库；本地测试邮件通过同一 Compose 项目邮件接收器验证。
- 未验证账户可正常使用允许的客户功能；商家手工认可仅作用于本商客关系。A 商家认可对 B 商家无效，越权请求被拒绝。
- /admin 进入商家认证或维护界面，客户不能访问商家功能；订单、行程等维护按商家授权隔离。
- 数据升级幂等、可验证，旧数据明确映射到试点商家；不建立长期双写或旧字段 fallback。
- 视口 390x844、360x800、768x1024、1440x1000 下操作可用，无横向溢出或遮挡；检查控制台、网络与真实截图。
- 手机主要热区至少 44px，相邻热区至少 6px；文字到内框至少 3px，视觉中心偏差最多 min(2px, 字形高 10%)。工具栏同排基线一致，布局采用明确内容栅格。截图先审整体再审局部，几何数据单独记录。
- Compose 列表仅新增或复用 bobuy-local 一组；本任务不影响其他应用，过程文件在任务目录内并于结束清理。
