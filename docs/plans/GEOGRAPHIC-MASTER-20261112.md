# 国家地区分级基础档案

## 主目标与用户要求
新增可选择的国家/地区、省县、市/区基础档案。目前预制日本全部省县和市区町村，其他国家/地区仅预制国家级档案。记录数据来源、数据日期及层级规则。

## 方法与范围
基于 origin/main 独立工作树实现，保护原工作区及其他任务改动。先核对现有基础资料、地址保存模型和权限，沿用项目成熟组件与分层。日本采用权威公开数据，国家地区采用有来源的标准代码。跨模块实现按 sub2api-agent 获取最小上下文建议，主 Agent 负责设计、代码、验证和验收。

用户后续纠正：只建立基础档案与选择接口。本批包含档案存储与初始化、按父级查询、基础资料查看与分级选择入口。个人资料、结账地址、订单、已有地址存储及其校验不在本批范围，不增加地址接入或改写历史数据。档案按预制数据只读发布，后续维护通过版本化数据迁移。生产部署先核实本次授权和现行门禁，不修改外部模型或共享环境配置。

## 完成标准与验证
1. 国家代码唯一，日本47都道府县和全量市区町村数据有来源、无孤儿或跨父级选择；其他国家仅国家档案。
2. 基础资料可查询选择，读取权限与既有基础资料一致，服务端拒绝不存在父级与非法查询。
3. 基础档案页面更改上级会清理下级，非日本国家显示仅有国家级数据。已有地址不做修改。
4. 版本化幂等迁移通过真实数据库验证，记录数据兼容与回滚边界。
5. 针对性测试覆盖有效与无效层级、权限、上级切换及数据完整性；冻结后统一执行适用正式门禁。
6. UI检查真实桌面及最窄支持视口，覆盖功能、Console、网络、截图。先检查运行截图再做几何与Gemini复核。控件字形四边安全距离至少3px，居中误差至多min(2px,字形高度10%)，操作热区间距至少6px，手机主要操作高度至少44px。布局沿用现有页面栅格与同角色尺寸。

## 数据与接口契约
- 共249个 ISO 3166-1 国家/地区根节点。来源为 pycountry 官方仓库 ISO 数据，页面名称使用浏览器标准 Intl.DisplayNames 按界面语言显示，代码保持稳定。
- 日本47个都道府县、1912个市区町村及政令市行政区。J-LIS47页代码集合覆盖日本邮政2026-10-30全部1892个市区町村代码，另外20个是政令指定都市本级。行政区与市同属第三级，区名称包含所属市，町村名称保留邮政的郡名前缀，用户仍只需三级选择。
- 公开读取：GET `/api/storefront/geographic-areas`；商家读取：GET `/api/merchant/geographic-areas`，沿用 AGENT 权限。省略parentCode列出国家；parentCode=JP列出都道府县；parentCode=JP-13列出东京都第三级。已存在叶节点返回200空数组；格式非法400，不存在父级404。无写接口。
- 响应沿用ApiResponse，data为数组，每项code、parentCode、level(1/2/3)、name、reading。国家代码为ISO alpha-2，日本省县为JP-加2位代码，第三级为JP-加5位代码，前导零保留。
- 管理页：`/admin/basic-data/geographic-areas`。默认日本，切换上级立即清空下级；隔离晚到响应，空数据提示与错误重试独立。没有地址迁移或消费者接入。
