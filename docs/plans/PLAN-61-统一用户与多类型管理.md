# PLAN-61 统一用户与多类型管理

## 目标与边界
- 2026-10-24：同一用户可勾选客户、商家其中一种或两种；购物车注册始终仅客户。平台管理端可创建和编辑账号类型、登录信息及启用状态。
- 独立/account注册允许选择客户、商家或两者；采用独立register-account接口，购物车register接口继续固定客户。注册不能设置平台管理员权限。双身份通过/customer专属接口查看自己的购买行程、订单与账单，商家工作台只查看自己的销售业务。
- 平台管理员是独立受保护权限，普通商家不可全局列出用户或授予商家身份。已有唯一 admin 账号在迁移中明确设为平台管理员，本地种子 agent 具备该权限。管理页面不提供授予平台管理员权限的开关。
- 保持四语、宝宝败品牌、响应式后台、匿名购物车、商客认可的商家独立性和已有生产发布门禁。
- 复用唯一 bobuy-local 环境；先本地端到端验证，再沿用已授权生产组发布。保护其他应用、热备与休眠状态。无新增环境，无批量业务数据修改。

## 方法与必要依赖
1. 主 Agent 核对身份、授权、用户接口和存储；外部模型仅提供最小实现建议。
2. 版本化迁移将旧单类型转换为类型集合，移除旧字段；原 AGENT 与 MERCHANT 统一商家能力 AGENT。数据库约束只接受非空、不重复的客户/商家集合。Flyway 再次启动不得重复迁移；短期回滚依赖备份恢复及停止写入窗口。
3. 认证每次请求从数据库加载全部能力，身份修改后旧令牌不能保留已撤销权限。平台管理接口使用独立 DTO，密码散列不返回，普通请求不能设置平台权限或邮箱验证事实。
4. 后台接入用户列表、搜索、创建/编辑抽屉、类型复选框和启用状态；四语资源同步；商家兼客户可使用两端功能。
5. 执行针对性单元/集成、迁移、构建与真实容器浏览器检查，再提交；发布记录包含备份恢复与保护状态证据。

## 完成标准与预置预算
- 创建客户、商家、双类型账号并能登录；至少一种类型；购物车携带恶意角色字段仍只能创建客户或被拒绝。
- 双类型账号能采购下单及进入商家工作台；商家认可客户不会授予平台权限；普通商家和客户对全局用户管理返回403。
- 用户名/邮箱唯一，创建要求有效密码，编辑空密码保持原密码，启停与权限更改对后续请求生效；平台管理员不能误停用自己。
- 迁移保留原账号、密码、商客关系与业务数据；数据库集合非法值负例失败，重复启动无变更。
- Chrome 360x800、390x844、768x1024、1440x1000，四语及长名称、双类型、空/搜索状态。桌面内容232px侧栏，手机16px安全边距；同类控件44px热区、6px间距；字形四边3px余量，中心误差min(2px,字形高10%)。列表横滚仅限表格；抽屉表单单列或双列，底部操作同组。
- 查看真实整体与原尺寸局部截图，功能、控制台、网络、响应式及字形/热区分项记录；Gemini建议由主 Agent 复核。生产写入仅用于必要验收且清除测试账号，优先只读及浏览器夹具。
