# 商品主图上传生产回归

## 生产基线

生产版本 `7842054a5bd4295a00b0075861f1bd8102131cf2`。登录 Chrome 打开商品编辑器的「图片与来源」，顶部「添加图片」触发 0 次文件选择器；下方选择入口在填写来源并核对前禁用，条件满足后可触发。此次生产复现没有页面错误或业务写入。#192 到此生产版本之间没有 `ProductCatalogPanel.tsx` 差异，尚未定位首次引入的提交。

## 修复和发布

商品编辑器的「添加图片」在点击事件内打开一个现有原生文件选择器。文件本地预览先于审核；提交图片仍需有效 HTTPS 来源及现有核对确认。保存主档后才关联图片，作用域和版本校验仍由现有服务执行。

默认官方图片来源独立于各图片的来源。空图库也可保存并在重开时回读；第一张图片上传默认使用该来源。后续上传可以覆盖本次来源，已有图片继续保留逐图来源。V51 加两个可空字段，分别用于商品和恢复检查点。迁移可重执行，旧应用可忽略新增 SQL 列，回滚应用时保留这一迁移。

## 复现与上线验证

- 从仓库根目录启动 `npm --prefix frontend run dev -- --port 5198`，运行 `node frontend/scripts/verify-gallery-picker.mjs`，需可用的 Playwright WebKit。脚本验证 390 和 1280 CSS px、取消后再选、先预览、空图库保存后刷新、主图上传回读、有图后继续打开选择器及逐图来源保留。浏览器使用隔离 HTTP 夹具。
- `ProductCatalogIntegrationTest` 经真实 HTTP 控制器和隔离数据库验证来源持久化及首图实际上传保存，包括越权、版本、恢复和公开状态。
- 发布后使用获准的隔离商品验证从选择到主图回读，iPhone Safari／Chrome／Edge 需要实际设备验证系统选择器。生产待补图商品应继续由商家按授权流程操作。开发和验收均不批量改写现有商品。

候选证据：WebKit 每个宽度观察到四次原生选择器事件、两次经审核上传，刷新后来源回读成功，既有图片保留逐图来源。390 px 档案列表请求在刷新时有两次 WebKit 夹具中断，已在记录中单列。图库接口和交互没有其他错误。定向前端 22 项、后端 8 项通过。V51 在隔离 PostgreSQL 上连续运行两次，均得到两个可空来源列。

## 2026-11-24 官方图上传定向修复（不发布）

授权范围仅为商品主档官方图片上传：浏览器按字节签名识别 JPEG/PNG/WebP/AVIF，可信的空 MIME 或 `application/octet-stream` 可继续处理；浏览器 MIME、扩展名与真实字节冲突时分别给出重命名/重新导出指导。输入/转换后大小、动画、解码、尺寸、来源、核对、标签、图库上限均返回可操作的四语错误。前端只准备一次提交文件，服务端仍独立解码、清洗和按原提交字节哈希复用；图片仅进入当前内部商户主档草稿，仍须审核保存才关联。

明确不改价格、库存、权限、分类、商品身份、其他商品字段、推荐关联或其他上传流程；79797 仅保留“分类树为单一路径”的只读说明。本批不合并、不部署、不操作生产。

功能与美观同时验收，须符合 `docs/ui-ux-guidelines.md`：
- 功能按本 issue 需求逐条通过，不改变未授权行为。
- 视觉与所在页面现有 UI 一致：复用已有 token 与组件，禁止原生未样式化控件，新控件与相邻控件齐高、同圆角档、间距统一。
- 具备默认 / hover / focus-visible / 选中或激活态；触控目标 ≥ 44px；键盘可操作；有可见标签或 aria-label；对比度足够。
- 四语文案（含较长的 en-US / ja-JP）在窄屏不溢出、不重叠。
- 独立验收应附 390px 与 1280px 的改动区域截图（含关键失败状态）；主移动断点下不得横向溢出。
- 只运行官方图上传直接相关的最小前后端测试；不得借此改动价格、库存、身份、权限、分类或推荐关联。

原始故障字节不可得，根因仍未确认。Costco 577268 的已核输入事实仅用于验收：官方页面指向 1200×1200 JPEG；错误命名为 `.webp` 且浏览器报告 `image/webp` 的 JPEG 必须得到明确冲突提示，真实 WebP 配合通用 MIME 应按字节签名转换为 PNG。
